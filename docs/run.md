# WordRay 运行与验证

## 1. 环境

已在本机确认可用：

| 组件 | 版本 |
| --- | --- |
| Rust / cargo | 1.97.1（`stable-x86_64-pc-windows-msvc`） |
| MSVC | 14.41（VS 位于 `X:\Visual-Studio\ide`） |
| Node | v22.22.0 |
| pnpm | 11.x |

## 2. 安装依赖

```powershell
cd X:\1_2026_project\wordRay
pnpm install
```

> pnpm 11 默认拦截依赖的构建脚本。`esbuild` 需要它来安装平台二进制，白名单写在
> `pnpm-workspace.yaml` 的 `allowBuilds` 里。若看到 `ERR_PNPM_IGNORED_BUILDS`，说明该白名单丢了。

## 3. 配置 DeepSeek Key

**推荐在界面里配**：点翻译面板右下角的「设置」即可打开设置窗口。
首次启动时如果还没配 Key，设置窗会**自动弹出**（否则用户按热键只会看到一句"没有配置"，不知道该去哪配）。

| 项 | 说明 |
| --- | --- |
| API Key | **用 Windows DPAPI 加密后落盘**，密文只能被当前 Windows 用户解开；明文不写文件、不进日志 |
| 接口地址 | 要带版本前缀（如 `/v1`），不要带 `/chat/completions` |
| 模型 | 默认 `deepseek-chat` |

设置窗里有一个「**测试连接**」，会**真跑一次流式请求**（而不是打 `/models`）——
验的就是实际使用的那条路，地址写错、模型名写错都会在这里暴露。

**也支持环境变量**（优先级低于设置文件）：

```powershell
$env:DEEPSEEK_API_KEY = "sk-你的key"
$env:DEEPSEEK_BASE_URL = "https://api.deepseek.com/v1"
$env:DEEPSEEK_MODEL    = "deepseek-chat"
```

取值优先级：**设置文件 > 环境变量 > 内置默认值**。设置窗会标出当前密钥来自哪一边，
避免"我明明设了却不生效"的困惑。

配置文件位置：`%APPDATA%\com.wuxian.wordray\config.json`（设置窗底部显示实际路径）。
首次运行 WordRay 时，如果新目录没有配置，会自动导入旧 `com.wuxian.selection-translator` 目录中的设置及加密密钥；已有新配置始终优先。

## 4. 启动

```powershell
.\scripts\dev.ps1   # 推荐：会先问 Key，再启动
pnpm start          # 等价于 tauri dev
pnpm tauri          # 同上
```

> `pnpm tauri:cli <子命令>` 才是原始 Tauri CLI（如 `pnpm tauri:cli icon`、`pnpm tauri:cli build`）。
>
> **系统托盘**：启动后，电脑右下角的通知区域会显示 WordRay 图标；如果被 Windows 收起，可在“显示隐藏的图标”菜单中找到。单击或双击图标会打开翻译面板，保留上次译文与窗口位置；右键菜单依次提供“打开 WordRay”“设置”“退出 WordRay”。面板的 ✕ 和 `Esc` 只隐藏窗口，设置窗口关闭后也能再次打开。完全退出请使用托盘菜单。

应用、网页、划词浮标和安装包共用 `icon-source.png`，原图圆角外侧的白底已处理为透明。按 doTime 的资源规格生成多尺寸 PNG/ICO、150×57 的 NSIS 顶部横幅和 164×314 的侧边图：

## 5. 用法

### 主路径：划词即现图标

1. 在任意应用里**拖选**一段中文，或**双击**选中一个词
2. 选区**右侧**浮现 WordRay 小图标
3. **点击图标** → 弹出翻译面板，**流式**显示中英双向译文
4. **Esc** 隐藏面板到托盘；「复制译文」把结果写进剪贴板
5. **按住面板标题栏即可拖到屏幕任意位置**

点空白处会收起图标。图标上按右键也能收起。

#### 输入与修改原文

从托盘菜单点击“打开 WordRay”后，可以直接在原文栏输入或粘贴文本，也可以修改已有原文。
点击原文栏外部或切换到其他窗口时，会按修改后的文本重新翻译，并重新生成词语对齐。
原文未修改时不会重复翻译；清空原文会同时清空译文。翻译失败时可点击“重试翻译”重试。
按原文判断翻译方向：含中文字符的文本译为英文，纯英文译为简体中文；历史缓存也会核对目标语言。

标题栏的布局按钮可切换上下排列与左右分栏。手动选择后会自动保存，重新翻译、
打开历史、隐藏再打开面板或退出重启均保持该布局；尚未手动选择时，仍按原文长度自动决定。

#### 拖动与位置固定

拖动面板后，位置会被**自动固定**：后续翻译不再把它挪回选区旁边。

不加固定的话，你刚拖到顺手的位置，下一次翻译就把它挪走了——拖动等于白做。

| 操作 | 效果 |
| --- | --- |
| 按住标题栏拖动 | 移动面板，松手即固定位置 |
| 标题栏「固定 / 已固定」按钮 | 手动切换固定与跟随 |
| 取消固定后 | 面板恢复"跟着选区走" |

> 实现说明：拖动走的是显式 API `getCurrentWindow().startDragging()`，**不是**
> `data-tauri-drag-region`——查过 tauri 2.12.1 的 Rust 源码，那个属性在这一版里没有被处理。
> 它需要的能力 `core:window:allow-start-dragging` 已在 `capabilities/default.json` 里声明。

#### 原文与译文的选词高亮

在面板内选中原文或译文的词，另一栏会高亮对应词语。完整的已有对齐项立即显示；
如果只选中词组内部的一部分（例如「词对齐模型」中的「模型」），会通过已配置的
翻译接口单独请求语义对齐，等待时显示「词语对齐中…」。同一次翻译中重复选择相同位置会复用结果。

高亮只使用实际对应的完整词语，不再按字符长度比例裁剪英文单词。没有明确对应或请求失败时，
面板显示提示并清除旧高亮。快速切换选词或开始新翻译时，迟到的旧结果不会覆盖当前选词。
鼠标拖选、双击和键盘调整选区均支持。目标词的位置由程序编号，接口只返回编号，
避免模型抄错单词或重复词前文而定位失败。对齐使用 JSON 模式，网络、服务和响应格式异常
最多尝试 3 次，单次最多 30 秒、整个过程最多 75 秒；账号或配置错误直接显示，不反复请求。
面板会显示重试进度。失败的具体原因直接显示在译文栏里，可点击「重试」再次尝试当前选区。
网络和模型仍可能失败，没有明确的语义对应时不显示猜测高亮。

#### 翻译历史

点击面板底部「设置」按钮右侧的「历史」按钮，打开历史窗口。成功完成的翻译会自动保存
原文和完整译文，最新记录排在前面，最多保留 **1000 条**；相同原文去重，超过上限时删除最早的记录。
翻译失败或未完成的流式结果不保存，相同原文优先复用历史译文。列表每次读取 50 条，滚动到底自动加载下一批；后续词语对齐失败不影响已有完整译文的保存。

历史通过 **Windows DPAPI** 加密后写入应用数据目录中的 `history.dpapi`，关闭应用或重启后仍可查看。
每条记录支持「复制译文」与「在面板中查看」；这两个操作使用保存内容，**不会重新请求翻译**。
在面板中查看后仍可选择词语，按现有规则请求词语对齐。关闭历史窗口只会隐藏它，可再次点击历史按钮打开。

#### 面板形态：竖排 / 左右分栏

内容长的时候，面板会**自动变宽并改成左右分栏**（原文在左、译文在右）。

| 触发条件 | 形态 | 尺寸 |
| --- | --- | --- |
| 原文 ≤ 80 字且不含换行 | 竖排（原文在上、译文在下） | 440 × 280 |
| 原文 > 80 字**或**含换行 | **左右分栏** | 860 × 300 |

- 宽版宽度最多占所在显示器的 **72%**，避免小屏上顶到屏幕外
- 两栏**各自滚动**，一栏很长时不会把另一栏挤出视口
- 只有「原文 + 译文」同时存在时才排两栏；否则（例如还没配 Key 时出现「原文 + 错误」）保持单栏
- 标题栏的**布局按钮可手动切换**；手动切换**不会移动面板**（你刚拖到的位置会保留）

> **注意**：形态判断**每次翻译都会重算**，所以手动切换只对当前这一次有效——
> 下一次遇到长文本仍会自动变宽。如果你希望手动选择能被记住（长文本也不再自动变宽），说一声即可加。

控制参数在 `src-tauri/src/main.rs`：

| 常量 | 默认 | 含义 |
| --- | --- | --- |
| `WIDE_LAYOUT_THRESHOLD` | 80 | 超过这个字数就用宽版 |
| `PANEL_WIDE_W` / `PANEL_WIDE_H` | 860 / 300 | 宽版尺寸 |
| `WIDE_MAX_SCREEN_RATIO` | 0.72 | 宽版宽度占显示器的上限比例 |

取词优先走 **UI Automation**，**全程不碰剪贴板**。

对于不通过 UIA 暴露文本的应用（**微信**、WPS 的 Qt 版、部分自绘界面），会自动退到
**剪贴板核实**：注入一次 `Ctrl+C`，用剪贴板的**写入序号**判断这次手势有没有真的选中文字，
取到后把原剪贴板内容放回去。这类应用里图标位置退化为"鼠标松开处"（拖选通常在文字右端松手，
观感基本一致）。

### 备选路径：全局热键

UIA 读不到选区的应用（部分 Office 控件、自绘界面）里，用控制台提示的全局热键触发，
这条路径会注入 `Ctrl+C` 从剪贴板取词。热键是候选链里第一个注册成功的那个，
控制台会打印实际生效的键：

```
[WordRay] 已注册全局热键：Shift + Alt + T
```

## 7. 已知限制

| 限制 | 影响 | 计划 |
| --- | --- | --- |
| **点击图标会抢走焦点** | 原应用失去焦点（功能不受影响，文本已在划词时读好） | 给图标窗加 `WS_EX_NOACTIVATE` |
| **UIA 读不到时退到剪贴板核实** | 这类应用（如微信）里每次划词都会短暂动一次剪贴板（随后还原）；图标位置用"鼠标松开处"而非文本右侧 | 用 UIA 矩形兜底 |
| **已知支持 UIA 的应用不走剪贴板** | 浏览器里拖链接、拖图片不会误弹图标——这是刻意保留的克制 | — |
| **剪贴板核实最长等 600ms** | 某次拖拽没选中文字时，取词线程会被占住这段时间（UI 与钩子不受影响） | 改为"按下快照"预判 |
| **Chromium 首次划词可能失败** | 浏览器/WebView2 的 UIA 树是"被问到才建"，冷启动第一次常读不到 | 已用多候选点 + 焦点元素重试；仍可能偶发 |
| **无"按下快照"** | 拖动一个**已选中**的元素时，可能误判为划词（现用"手势起点须在选区附近"挡掉大部分） | 按下那一刻拍选区快照 |
| **UIA 在主进程内调用** | 第三方 provider 卡死会占住取词线程（UI 与钩子不受影响） | 移入可重建的 helper 子进程 |
| 混合 DPI 未处理 | 非 100% 缩放下图标/面板位置可能有偏差 | 对 Q3 |
| 无单实例保护 | 别同时开两个实例，会抢热键、装两个鼠标钩子 | 对 Q3 |

| 日志 | 含义 |

## 9. 代码结构速览

```
src/                          React 前端（Vite，main / icon / settings / history 四个入口）
├── App.tsx                   翻译面板
├── main.tsx                  翻译面板入口（index.html）
├── TranslateIcon.tsx         划词图标（注意：不能叫 Icon.tsx，见下）
├── icon.tsx                  图标窗入口（icon.html）
├── SettingsView.tsx          设置窗口
├── settings.tsx              设置窗入口（settings.html）
├── HistoryView.tsx           翻译历史窗口
└── history.tsx               历史窗入口（history.html）

src-tauri/src/
├── main.rs                   窗口编排、命令、热键、划词分发
├── mouse_hook.rs             WH_MOUSE_LL 全局鼠标钩子（只发事件，绝不阻塞）
├── gesture.rs                手势状态机 + 位置守卫（纯逻辑，9 个单测）
├── uia.rs                    UI Automation 读选区文字与矩形
├── clipboard.rs              剪贴板注入取词（热键备选路径用）
├── deepseek.rs               DeepSeek 流式客户端
├── selection_alignment.rs    选词语义对齐与重试
├── settings.rs               设置与 DPAPI 密钥存储
└── history.rs                最新 1000 条翻译历史与 DPAPI 持久化
```

> ⚠️ **命名坑**：Windows 文件系统不区分大小写，`src/Icon.tsx` 与 `src/icon.tsx`
> 是**同一个文件**。曾因此把入口文件覆盖成组件，导致构建产物引用错 chunk。
> 组件文件名请用 `TranslateIcon.tsx` 这类不冲突的名字。
